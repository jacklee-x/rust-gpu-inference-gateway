rust-gpu-inference-gateway — 整体架构总览

三层架构的完整视图：Rust 异步网关（任务调度 + 可观测性）→ 推理核心（C++ 原型 / llama.cpp GPU 双变体）→ Python 工具链（演示 / 基准 / 测试），外加本地脚本与 Docker 两套部署路径。本页 4 张逻辑图 + 逐层解读，全部自包含、离线可用。

语言：Rust 780 行 · C++ 547 行 · Python 4 脚本 网关：axum + tokio，4 端点 调度：有界队列 + 自适应 Worker Pool 核心协议：infer | llama-chat 部署：本地脚本 | Docker Compose 可观测：tracing + 无依赖 Prometheus

02请求生命周期（7 步时序）

一次 POST /infer 从客户端到推理核心再返回的完整旅程。背压（503）、超时（504）、指标采集都发生在这些步骤中。

03自适应 Worker Pool 机制（src/worker_pool.rs）

并发度不是固定值，而是随队列积压动态伸缩：队列越深、派发越多的并发 worker；空闲时自动回落。这是本仓库最"有设计含量"的调度机制。

图 ③ 伸缩策略与三种状态

默认配置：MIN_CONCURRENCY=1，MAX_CONCURRENCY=4。调度器每派发一个任务就重算一次。

04双运行模式对照：infer vs llama-chat

同一套网关代码通过 CORE_PROTOCOL 环境变量切换后端，是"原型可跑通 + 生产可升级"设计的关键。

维度infer（默认 / CPU 模式）llama-chat（GPU 生产模式）
后端服务C++ 原型 core（cpp_inference/inference_core.cpp）llama-server（llama.cpp + CUDA）
网关调用端点POST {core}/infer（自定义线格式）POST {core}/v1/chat/completions（OpenAI 兼容）
响应解析反序列化 InferResponse（字段直接对应）解析 choices[0].message.content + usage + timings
延迟/Token 来源core 返回（原型写死 5ms 假数据）llama-server 真实 timings.predicted_ms / usage
模型注册表静态快照（qwen2.5-0.5b + llama-7b/13b + mistral-7b）动态同步：GET /v1/models 每 REGISTRY_REFRESH_SECS 拉取（含 alias 校验）
多模型否（单一原型）是（LLAMA_MODELS_DIR 路由模式，子进程懒加载）
适用场景CI / Docker CPU 镜像 / 教学演示 / 无 GPU 环境真实 GPU 推理、多模型服务
协议别名其它任何值均回退到 inferllama-chat / llama / openai 均触发
CoreProtocol 枚举（main.rs 131-159）网关把"后端差异"收敛为协议选择 + 两条调用函数（call_infer_protocol / call_llama_chat_protocol），Handler、队列、调度、指标完全不受影响 —— 这是本仓库抽象做得最干净的一处。

05配置矩阵（环境变量）

全部配置走环境变量，同一二进制适配本地 / Docker / CI 三种环境（src/main.rs Config::from_env，161-225 行）。

变量默认值作用
BIND_ADDR / PORT127.0.0.1:8080网关监听地址；Dockerfile 覆盖为 0.0.0.0:8080

07逐层详细解读

按上图 6 个关键组件逐一展开：职责、实现要点、与其他层的关系。

7.1 客户端与请求入口

  • 请求形状：POST /infer，body = {model, input, options{max_tokens, temperature, top_p}, request_id?}（InferRequest，main.rs 41-48）。request_id 可省略，网关会补 UUID。
  • 三种客户端：curl / PowerShell（README 示例）；Python demo client（httpx）；benchmark 脚本。全部打向 127.0.0.1:8080（网关），从不直连核心 —— 网关是唯一入口。
  • 模型校验前置：handler 第一步查注册表，未知模型直接 400（不浪费队列与核心资源），并计入 inference_responses_total{status="invalid_request"}。

7.2 Rust 网关核心（src/main.rs）

  • 启动装配（main，230-334）：tracing 初始化 → Config::from_env → 建有界 mpsc 队列 → 建共享 reqwest Client → Metrics/ModelRegistry → AdaptiveWorkerPool → spawn dispatcher_loop（后台常驻）→ llama-chat 模式额外 spawn registry_sync_loop → axum Router 4 路由 → serve。
  • infer_handler 六步（419-503）：① 校验模型；② 生成 UUID 并 stamp + 开 tracing span；③ 建 oneshot 通道；④ try_send 入队（失败 → 503 queue_full）；⑤ tokio::time::timeout 等待；⑥ 按结果分支：成功 200 / 核心报错 500 / worker 取消 500 / 超时 504。每分支都调 finish_request 落指标。
  • dispatcher_loop（345-381）：队列消费方。每取一个 Job：pool.reconfigure(queue_len) 伸缩 → pool.acquire() 等许可 → spawn 异步 worker（调核心 + oneshot 回传 + drop permit）。并发度 = 池大小，天然限流。
  • 双协议调用（514-628）：call_inference_core 按 CoreProtocol 分派；infer 协议反序列化 InferResponse；llama-chat 协议组装 OpenAI chat body、解析 choices/usage/timings，把真实延迟写进 usage.latency_ms。

7.3 自适应 Worker Pool（src/worker_pool.rs，157 行）

  • 结构：Semaphore（并发许可）+ current/min/max 原子计数。构造时 clamp（min ≥1 且 ≤ max）。
  • reconfigure(queue_len)：目标值 = min + queue_len/2 并 clamp；比 current 大 → add_permits，小 → forget_permits；用 CAS 循环防止并发重算竞态（只影响伸缩精度，不影响正确性）。
  • acquire()：取 OwnedSemaphorePermit，取不到就 await —— 这就是"超并发时 worker 自然排队"的背压实现。
  • 不打断在途任务：缩容只回收"未来的许可"，运行中的 worker 持有 permit 照常跑完，优雅降级。
  • 自带 6 个单元测试（起始值 / clamp / 伸缩 / 上限 / 许可一致性），覆盖核心行为 —— 全仓唯一的测试模块。

7.4 指标系统（src/metrics.rs，215 行）

  • 零依赖：计数器用 AtomicU64，直方图用 Mutex<[u64;9]>，render() 直接拼 Prometheus 文本格式（0.0.4），无需 prometheus crate —— 注释明确说明生产可换正式库。
  • 指标族：inference_requests_total（接受数）、inference_requests_in_flight（在途）、inference_worker_pool_size/max（池伸缩，由调度器更新）、inference_responses_total{status=ok|error|timeout|queue_full|invalid_request}、延迟 sum/count/bucket（1..1000ms 9 桶 + +Inf）。
  • 桶写入用"小于等于则逐桶 +1"的朴素累计（O(9) 每请求），换取无锁直方图。

7.5 模型注册表（src/models.rs，129 行）

  • RwLock 保护 models 列表 + 大小写不敏感 known_names 集合（含别名）。
  • 静态模式（Default）：infer 协议下的内置快照 —— qwen2.5-0.5b-instruct（loaded）+ llama-7b/13b、mistral-7b（available），保证无核心可查时也能校验与演示。
  • 动态模式：registry_sync_loop 每 REGISTRY_REFRESH_SECS 拉取 GET {core}/v1/models，10 秒超时保护；失败只告警、保留上一快照（核心短暂不可达不会清空注册表）。llama-server 的 alias 也会进入 known_names，别名请求可通过校验。

7.6 推理核心双变体（C++ 原型 / llama-server）

C++ 原型（详见 docs/cpp-inference-core.html）

  • 手写原生 Socket HTTP 服务，547 行零依赖，监听 127.0.0.1:8081。
  • GET /health（编排探测）+ POST /infer（InferRequest → InferResponse）。
  • CPU 回退（toupper 变换）/ CUDA kernel（__CUDACC__ 编译钩子）双路径。
  • 每连接一线程（detach），无并发上限 —— 原型取舍。

llama-server（GPU 生产，README §0 路线）

  • llama.cpp + CUDA 编译，提供 OpenAI 兼容 /v1/chat/completions 与 /v1/models。
  • 单模型模式（--model + --alias）或路由模式（LLAMA_MODELS_DIR，多模型懒加载子进程）。
  • 由 start-llama-server.sh 启动：--host 127.0.0.1 --port 8081 --gpu-layers 99 --ctx-size 2048，120s 健康等待。
  • 网关以 CORE_PROTOCOL=llama-chat 对接，注册表实时镜像其模型列表。

7.7 Python 工具链

  • demo/client.py：argparse（--model/--input）+ httpx 请求，打印 JSON —— 演示链路的最小闭环。
  • benchmark/benchmark.py：固定 payload 循环 10 次，perf_counter 计时，输出单次与平均延迟 —— 配合 /metrics 验证 Worker Pool 伸缩的观测工具。
  • tests/test_end_to_end.py：pytest 断言 200 + status ok + output 存在；trust_env=False 屏蔽 CI 代理环境变量干扰（踩坑修复的产物）。
  • tools/generate_input.py：输出标准示例 JSON，供手测与文档复用。

7.8 编排与部署

  • 本地开发（start-dev.sh）：缺二进制先跑 build.sh → 启动 C++ core → 轮询 /health（15s 超时）→ 启动网关（PORT 传入）→ 再验 /health → 写 PID 文件；任一步失败执行 rollback（kill 已启进程）并保留日志供排查。stop-dev.sh 按 PID 文件清理。
  • GPU 模式（start-llama-server.sh/.ps1）：先杀残留实例避免端口冲突；单模型/路由二选一；CUDA bin 加入 PATH（Windows 版）；120s 等待 llama-server 健康后打印网关启动命令。
  • 容器化（docker-compose.yml + Dockerfile ×2）：gateway 镜像（rust:1.81 多阶段，ENV BIND_ADDR=0.0.0.0:8080 CORE_URL=http://inference_core:8081）+ core 镜像（gcc:13 → slim）；compose 用 healthcheck + depends_on: service_healthy 保证启动顺序；wget 做健康探测。

08关键设计决策回顾

决策理由代价 / 后续
Rust 网关 + C++ 核心 + Python 工具链各语言做最擅长的事：Rust 异步并发、C++ GPU 生态、Python 自动化跨语言契约靠 JSON 对齐，需测试守护
有界 mpsc 队列 + try_send → 503背压前置：队列满立刻拒绝，不拖垮 worker客户端需处理 503 重试
自适应 Worker Pool（queue_len/2 策略）空闲省资源、积压提吞吐，避免固定并发两难伸缩粒度粗糙，生产可用 HPA 思路替换
CoreProtocol 枚举抽象双后端原型与生产共享同一网关代码，零成本切换infer 协议随 llama-chat 上线逐渐弃用
静态 vs 动态模型注册表无核心环境可演示；有核心环境镜像真实模型同步是轮询，未来可换推送/事件
零依赖 Prometheus 文本指标演示阶段避免引入 prometheus crate 复杂度生产换正式库或 tracing 导出器
环境变量全配置同一二进制适配本地/容器/CI配置项渐多后可引 config crate
总体评价这是一个"分层清晰、契约明确、取舍诚实"的教学级推理网关：Rust 侧展示了 async 调度、背压、自适应并发与可观测性的完整工程套路；C++ 侧展示了 GPU 集成的双路径骨架；Python 侧补齐了演示/基准/测试闭环。真正的 GPU 生产力已由 llama.cpp 生态接管 —— 仓库的价值在于把三套技术栈用清晰的边界拼成一条可运行的链路。
