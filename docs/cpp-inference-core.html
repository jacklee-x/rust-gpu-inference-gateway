01系统定位：C++ 推理核心在整个仓库中的角色

该仓库是三层架构（Rust 网关 → C++ 推理核心 → Python 工具链）。C++ 部分是唯一真正执行"推理"的服务，但当前实现为轻量原型。

  • 定位：C++ core 是一个被 Rust 网关通过 reqwest 远程调用的本地推理服务（HTTP over 127.0.0.1），网关不直接执行模型。
  • 双协议：网关按 CORE_PROTOCOL 环境变量选择 —— infer（调用本 C++ 原型的 POST /infer）或 llama-chat（调用 llama-server 的 /v1/chat/completions）。
  • 设计意图：演示"请求从客户端出发，穿过 Rust 异步网关，最终落到 GPU 执行"的完整链路；C++ 侧预留了 __CUDACC__ 编译钩子作为真实 CUDA 内核的插入点。
  • 当前形态：不是生产级 LLM 引擎 —— CPU 路径只是对输入做 大写变换；CUDA 路径只是逐字节 +1 的玩具 kernel。真正的模型执行由 llama-server（llama.cpp + CUDA）承担。
一句话总结一个零依赖、跨平台（Win/Linux/macOS）、手写原生 Socket 的极简 HTTP 推理服务：main → serve_forever → accept 循环 → 每连接一线程 → 路由 /health | /infer → 解析 JSON → CPU/CUDA 推理 → JSON 响应。

3.3 文本工具：trim 与 json_escape 53-77

std::string trim(const std::string& value) {
    const std::string whitespace = " \t\r\n";
    const auto begin = value.find_first_not_of(whitespace);
    if (begin == std::string::npos) { return ""; }
    const auto end = value.find_last_not_of(whitespace);
    return value.substr(begin, end - begin + 1);
}

std::string json_escape(const std::string& value) {
    std::string output; output.reserve(value.size() + 8);
    for (char ch : value) {
        switch (ch) {
            case '\\': output += "\\\\"; break;
            case '"':  output += "\\\""; break;
            case '\n': output += "\\n"; break;
            case '\r': output += "\\r"; break;
            case '\t': output += "\\t"; break;
            default:   output += ch; break;
        }
    }
    return output;
}
  • trim：去掉首尾空白，用于解析 Content-Length 头（stoul 前的必要清洗）。
  • json_escape：在输出侧做 JSON 字符串转义（反斜杠、双引号、换行/回车/Tab），防止模型输出或用户输入破坏响应 JSON 结构。注意它不转义控制字符（如 \x00），转义集是演示级最小集。

std::string find_json_string_value(const std::string& json, const std::string& key) {
    const std::string key_pattern = "\"" + key + "\":\"";
    const auto pos = json.find(key_pattern);
    if (pos == std::string::npos) { return ""; }
    const auto start = pos + key_pattern.size();
    const auto end = json.find('"', start);
    if (end == std::string::npos) { return ""; }
    return json.substr(start, end - start);
}

int find_json_int_value(const std::string& json, const std::string& key, int fallback = 0) {
    const std::string key_pattern = "\"" + key + "\":";
    const auto pos = json.find(key_pattern);
    if (pos == std::string::npos) { return fallback; }
    const auto start = pos + key_pattern.size();
    const auto end = json.find_first_not_of("0123456789-", start);
    const std::string digits = json.substr(start, (end == std::string::npos ? json.size() : end) - start);
    if (digits.empty()) { return fallback; }
    return std::stoi(digits);
}

3.5 请求模型与解析 parse_request_body 153-206

struct InferenceRequest {
    std::string model = "llama-7b";
    std::string input = "hello world";
    int max_tokens = 32;
    float temperature = 0.8f;
    float top_p = 0.95f;
};

InferenceRequest parse_request_body(const std::string& body) {
    InferenceRequest request;
    request.model = find_json_string_value(body, "model");
    if (request.model.empty()) { request.model = "llama-7b"; }   // 缺省模型

    request.input = find_json_string_value(body, "input");
    if (request.input.empty()) { request.input = "hello world"; }

    request.max_tokens  = find_json_int_value(body, "max_tokens", 32);
    request.temperature = find_json_float_value(body, "temperature", 0.8f);
    request.top_p       = find_json_float_value(body, "top_p", 0.95f);

    // sanitize：非法值回退到安全默认
    if (request.max_tokens <= 0)      { request.max_tokens = 32; }
    if (request.temperature <= 0.0f)  { request.temperature = 0.8f; }
    if (request.top_p <= 0.0f)        { request.top_p = 0.95f; }

    // 兼容嵌套 options 形状
    const std::string nested = extract_value_from_nested_options(body, "max_tokens");
    if (!nested.empty()) { request.max_tokens = std::stoi(nested); }
    return request;
}
  • 缺省优先：所有字段都有合理默认值（llama-7b / hello world / 32 / 0.8 / 0.95），"解析失败 → 回退默认"是全程策略，服务永不因坏输入崩溃。
  • sanitize 层：负数/零值被重置，保证后续推理参数始终在安全区间。
  • 嵌套覆盖：若 options.max_tokens 存在则覆盖顶层值 —— 注意这里嵌套优先级高于顶层。
  • 无参数校验上限（如 max_tokens=10^9 也接受），演示级取舍。

3.7 推理实现：CPU 回退 与 CUDA 路径 216-294

std::string run_cpu_inference(const InferenceRequest& request) {
    std::string text = request.input;
    // naive normalization: uppercase the input
    std::transform(text.begin(), text.end(), text.begin(), [](unsigned char c) {
        return static_cast<char>(std::toupper(static_cast<unsigned char>(c)));
    });
    std::ostringstream oss;
    oss << "C++ CPU inference result for model=" << request.model
        << " input=" << json_escape(request.input)
        << " tokens=" << request.max_tokens
        << " temperature=" << request.temperature
        << " top_p=" << request.top_p
        << " normalized=" << json_escape(text);
    return oss.str();
}

#if defined(__CUDACC__)
std::string run_cuda_inference(const InferenceRequest& request) {
    int device_count = 0;
    cudaGetDeviceCount(&device_count);
    if (device_count <= 0) { return run_cpu_inference(request); }  // 无 GPU → 回退

    std::string input_copy = request.input;
    std::vector<char> bytes(input_copy.begin(), input_copy.end());
    bytes.push_back('\0');

    char* device_buffer = nullptr;
    cudaMalloc((void**)&device_buffer, bytes.size());
    cudaMemcpy(device_buffer, bytes.data(), bytes.size(), cudaMemcpyHostToDevice);

    int block_size = 256;
    int grid_size = (static_cast<int>(bytes.size()) + block_size - 1) / block_size;
    cuda_kernel<<<grid_size, block_size>>>(device_buffer, static_cast<int>(bytes.size()));
    cudaDeviceSynchronize();

    char host_buffer[1024] = {0};
    cudaMemcpy(host_buffer, device_buffer, sizeof(host_buffer), cudaMemcpyDeviceToHost);
    cudaFree(device_buffer);
    ...
}

// 玩具 kernel：逐字节 +1
__global__ void cuda_kernel(char* buffer, int length) {
    const int idx = blockIdx.x * blockDim.x + threadIdx.x;
    if (idx < length) { buffer[idx] = static_cast<char>(buffer[idx] + 1); }
}
#else
// 非 nvcc 编译时，CUDA 入口直接走 CPU
std::string run_cuda_inference(const InferenceRequest& request) {
    return run_cpu_inference(request);
}
#endif
  • 双层回退设计：编译期无 CUDA（#else 分支）→ 恒走 CPU；编译期有 CUDA 但运行期无设备（cudaGetDeviceCount == 0）→ 再回退 CPU。任何环境都能跑通端到端链路。
  • CUDA 标准流程：H2D 拷贝 → kernel 启动（grid 按输入长度向上取整，block=256 线程）→ cudaDeviceSynchronize → D2H 回拷 → cudaFree。这个骨架正是真实模型推理（TensorRT / ONNX Runtime CUDA provider）的通用形态。
  • 演示级问题：未检查每个 CUDA API 的返回值（错误被吞）；host_buffer[1024] 若输入超过 1KB 会截断；kernel 语义（逐字节 +1）与"推理"无关。
  • std::toupper 前强制转 unsigned char，避免负 char 的 UB —— 这是正规写法。

3.9 HTTP 读取层 read_available_data / read_http_request 315-387

bool read_available_data(int socket_fd, std::string& output, size_t expected_bytes) {
    output.clear();
    char buffer[4096];
    size_t received_total = 0;
    while (received_total < expected_bytes) {
        const int chunk_size = static_cast<int>(std::min<size_t>(sizeof(buffer), expected_bytes - received_total));
        const int received = recv(socket_fd, buffer, chunk_size, 0);
        if (received <= 0) { return false; }       // 连接关闭/出错
        output.append(buffer, static_cast<size_t>(received));
        received_total += static_cast<size_t>(received);
    }
    return true;
}

std::string read_http_request(int socket_fd) {
    std::string request; char buffer[4096];
    while (true) {
        const int received = recv(socket_fd, buffer, sizeof(buffer), 0);
        if (received <= 0) { return request; }      // 连接关闭 → 返回已读内容

        const size_t content_length = static_cast<size_t>(std::stoul(length_value));

void send_response(int client_socket, const std::string& status_line, const std::string& payload) {
    const std::string response =
        status_line + "Content-Type: application/json\r\n"
        + "Content-Length: " + std::to_string(payload.size()) + "\r\n"

3.11 核心处理器与路由 handle_client_connection 403-477

void handle_client_connection(int client_socket) {
    const std::string request = read_http_request(client_socket);
    if (request.empty()) {
        send_response(client_socket, "HTTP/1.1 400 Bad Request\r\n", build_error_json("empty request", 400));
        closesocket(client_socket); return;
    }
    // 解析请求行：METHOD PATH VERSION
    const auto request_line_end = request.find("\r\n");
    const std::string request_line = request.substr(0, request_line_end);
    std::istringstream iss(request_line);
    std::string method, path, version;
    iss >> method >> path >> version;

    if (method == "GET" && path == "/health") {
        const std::string payload = "{\"status\":\"healthy\",\"engine\":\"c++-cuda-ready\"}";
        send_response(client_socket, "HTTP/1.1 200 OK\r\n", payload);
        closesocket(client_socket); return;
    }

    if (method == "POST" && path == "/infer") {
        const auto body_start = request.find("\r\n\r\n");
        if (body_start == std::string::npos) { ...400 "missing body"... }
        const std::string body = request.substr(body_start + 4);
        const InferenceRequest request_details = parse_request_body(body);
        const std::string payload = build_inference_json(request_details);
        send_response(client_socket, "HTTP/1.1 200 OK\r\n", payload);
        closesocket(client_socket); return;
    }

    // 未知路由
    send_response(client_socket, "HTTP/1.1 404 Not Found\r\n", build_error_json("route not found", 404));
    closesocket(client_socket);
}
  • 路由表：仅 3 条规则 —— GET /health → 200 healthy；POST /infer → 200 推理结果；其余 → 404。health 的 engine:"c++-cuda-ready" 字段是给编排脚本（start-dev.sh 等）探测用的。
  • 每个分支结束后都关闭套接字 —— 无泄漏路径；错误分支复用 build_error_json 保证响应结构一致。
  • 每连接一个 std::thread + detach()：accept 循环不被阻塞，但无并发上限 —— 高并发下线程数无限增长（C10K 问题的反面教材，原型可接受）。

    address.sin_addr.s_addr = inet_addr("127.0.0.1");   // 只监听回环

    if (bind(server_fd, ...) < 0)  { std::cerr << "Bind failed on port " << port << std::endl; std::exit(1); }
    if (listen(server_fd, 16) < 0) { std::cerr << "Listen failed" << std::endl; std::exit(1); }

    std::cout << "C++ inference core listening on 127.0.0.1:" << port << std::endl;
    while (true) {
        const int client_fd = accept(server_fd, ...);
        if (client_fd < 0) { std::cerr << "Accept failed" << std::endl; continue; }
        std::thread client_thread(handle_client_connection, client_fd);
        client_thread.detach();
    }
}

int main(int argc, char** argv) {
    int port = 8081;
    if (argc >= 3 && std::string(argv[1]) == "--port") { port = std::stoi(argv[2]); }
    std::cout << "Starting C++ inference core with optional CUDA path" << std::endl;
    serve_forever(static_cast<uint16_t>(port));
    return 0;
}
  • 初始化失败即退出（std::exit(1)）：socket/bind/listen 任何一步失败都无法提供服务，快速失败让编排脚本（start-dev.sh 会等待 /health 并回滚）及时感知。
  • 只绑定 127.0.0.1（回环）：安全设计 —— 服务不暴露到外部网络，只服务本机 Rust 网关。
  • accept 失败仅打印并 continue（不退出），提高健壮性；listen 队列 16。
  • 主线程 = accept 循环，工作线程 = 连接处理，两者通过 detach() 解耦 —— 经典"每连接一线程"模型。
  • main 的 CLI 仅支持 --port N（run_core.sh 与 Dockerfile 都以该参数启动）。

3.13 构建与部署配套（build.sh / run_core.sh / Dockerfile） 仓库文件

# build.sh 的编译器选择策略（优先级递减）：
#   1) nvcc   → 启用 __CUDACC__，编译出带 CUDA kernel 的二进制
#   2) g++    → -std=c++17 -O2 -pthread，纯 CPU 回退
#   3) clang++→ 同上

  • 编译矩阵：同一份源码通过编译器选择产出两种二进制 —— 这正是 __CUDACC__ 双路径设计的落地：有 nvcc 环境自动出 CUDA 版，否则自动出 CPU 版，开发者无需改代码。
  • 运行脚本：run_core.sh [port] 前台运行并透传 --port；scripts/start-dev.sh 会同时拉起 C++ core 与 Rust 网关并做健康检查（等待 /health 成功、失败回滚）。
  • 容器化：Dockerfile 多阶段构建（gcc:13 编译 → debian-slim 运行），仅打包 CPU 回退二进制；compose 中 CORE_URL=http://inference_core:8081 把网关与 core 连成服务网络。

05局限性与演进路线

当前局限（原型取舍）

  • 手写 JSON 解析：字符串匹配式提取，遇到嵌套/转义/非法数字会误解析或抛异常，应换 nlohmann/json 或 rapidjson。
  • 每连接一线程且无上限：并发一高线程数就失控；无连接超时，慢客户端可永久占住线程。
  • 阻塞式 recv + 无请求超时：不适合高吞吐，应引入 epoll/io_uring 或直接上 asio。
  • 非真实推理：CPU 只是 toupper，CUDA 只是逐字节 +1；latency_ms 写死 5。
  • 健壮性缺口：CUDA API 返回值未检查；stoul/stoi 异常未捕获（可导致进程 terminate）；无日志/指标/鉴权。

演进路线（README / cpp_inference/README.md Roadmap）

  • 短期：把 CPU 回退换成真实 CUDA kernel + 模型加载；集成 ONNX Runtime 或 TensorRT 做生产推理。
  • 中期：请求批处理（batching）、动态模型加载/卸载、模型状态查询。
  • 长期：gRPC + protobuf 替代手写 HTTP；Kubernetes 部署；Solana/zk PoC。
  • 已落地（仓库现状）：llama.cpp + CUDA 的 llama-chat 模式、动态模型注册表、自适应 Worker Pool —— 仓库的 GPU 演进实际发生在 llama-server 侧，而非本 C++ 文件。
